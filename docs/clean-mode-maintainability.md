# 清爽模式维护与兼容性审查

审查日期：2026-10-01。目标实现：0.13.1-cleanmode-r4。当前结论：相较旧版明显改善，可维护性中等；跨版本行为一致性尚未验证，不能作为已兼容多个抖音版本的成品提交。

## 职责与依赖

| 部件 | 职责 | 宿主依赖与维护风险 |
| --- | --- | --- |
| CleanModePlaybackState | 播放、暂停、滚动、直播、离开状态转换 | 纯 Kotlin；8 项单元测试覆盖状态转换，不覆盖 Android UI |
| CleanModeHooker | 持有所属 panel/fragment，提交、重申、撤销本模块原生命令，调用原生布局适配 | BaseListFragmentPanel 的具名入口、播放事件码 2/3/4、原生命令位 8 和 caller 去重语义；入口签名及行为仍需逐版本核对 |
| NativeCleanModeSymbols / HookInfo | 解析并缓存服务、命令及混淆字段 | DexKit 语义匹配替代固定混淆名；唯一匹配是必要条件，但不代表新版本语义必然相同 |
| CleanModeChromeHooker / NativeCleanModeChromeSymbols | 限定当前所属 Activity 的主页顶部、阴影、底栏，拦截最终显示，退出时恢复仍待执行的显示请求 | 具名控件类、日志字符串、setHasFixSize 调用关系及 HomePageUIService；宿主控件架构更换会使映射失效 |
| CleanModeWindowHooker | 主页系统栏全屏 | Android Window/Insets API 与 MainActivity 类名；范围是整个 MainActivity，其他主页 tab 也保持系统全屏，需要产品行为回归 |
| DanmakuViewHooker | 收集弹幕容器，扩充原生白名单，调用宿主遍历分解共享祖先的隐藏请求 | DanmakuModule 入口、原生 presenter 的遍历/优先级语义；38.8.0 用户确认弹幕可见，其他版本未验收 |

优势是状态、窗口、弹幕、主页栏分别维护，不再依赖固定像素、整棵 decor 树扫描、触摸转发或定时反复隐藏。弱引用限制页面持有；本模块仅撤销自己的 caller；符号集中并纳入现有缓存；执行失败记录堆栈。

剩余成本主要在宿主协议而非 Kotlin 代码量。原生状态回调仍可能在动画、页面切换时重入；页面所有权和恢复路径必须一起 review。r3 的评论刷新编译、状态测试均通过，却未通过实机反馈，说明这些检查不足以验收界面时序。

## r4 审查重点

删除无效的评论 View.post 刷新，只保留播放/切换视频所需的原生命令重申。主页栏保护放在原生优先级管理器选出结果之后的最终渲染方法，修改实际显示参数，不把 GONE 写入宿主的优先级请求表。

顶部仅匹配 HomePageUIService 返回的标题栏与阴影 ID；底部仅匹配专用 MainBottomTabViewNew；两者要求 Activity 与当前清爽页面一致。暂停/离开时先清除命令所有权，再撤销命令，最后恢复宿主未能再次渲染的待显示请求。后续有效隐藏请求会清除此前待显示请求，避免退出时错误显示。没有全局 View.setVisibility / setAlpha Hook，没有新增延迟轮询。

新映射在全部必要成员解析成功后才安装保护。映射失败记录异常并禁用该保护，基础原生清屏仍可运行，评论关闭后栏位可能重新出现。此降级属于已知限制，不能标记为完整兼容。Hook 安装失败也需查日志，不能仅凭 APK 构建成功判断有效。

## 兼容性证据

| 宿主 | 静态分析 | 运行时证据 | 结论 |
| --- | --- | --- | --- |
| 抖音 38.8.0 | 有本地 dex、反编译调用链与签名 | 用户确认 r3 弹幕正常，r3 关闭评论后上下栏仍半透明；r4 待实机验收 | 部分功能已确认；评论修复尚未验收 |
| 其他抖音版本 | 本次未核对 | 本次未测试 | 未验证 |

不能将某个 DexKit 查询得到唯一结果等同于跨版本行为一致。正式合并前，至少需要覆盖项目宣称支持的宿主版本，并记录 APK 版本/哈希、模块版本、映射结果、关键场景结果和异常日志。

## 提交前 review 与验收门槛

1. 符号解析限定类、签名及语义依据，唯一匹配失败要明确报错，避免无依据的多重兜底。
2. 检查清屏所有权、原生优先级模型、异常退出及页面销毁恢复，不将播放中的 UI 修复扩散到其他页面。
3. 运行格式检查、状态测试、构建；这些只作为代码检查，另行完成设备回归。
4. 设备覆盖冷启动首个视频、连续暂停/继续、直播预览、返回键/下滑关闭评论、评论输入键盘、评论关闭前切后台/离开页面、弹幕开关与发送、搜索/作者页/其他 tab，以及相关功能组合。
5. 对每个支持版本重复上述设备回归；动画期间无残留，暂停可操作，离开后控件恢复，弹幕仍遵循宿主开关。未测项保留“未验证”。

本次没有连接 Android 设备，也没有建立宿主 UI 自动化测试。完成上述门槛后，才能把目前“中等、依赖人工宿主回归”的维护状态提升为可持续验收的跨版本实现。
